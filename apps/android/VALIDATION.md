## Независимое ревью

Отдельный агент проверил проект без изменения файлов. По замечаниям исправлены:

- Изменение старых `updated_at` во время миграции: прежние триггеры снимаются до заполнения новых полей; сохранение дат проверено тестом.
- Гонка применения серверной страницы и локального напоминания: операции SQLite выполняются последовательно.
- Гонки отмены/запуска веб-репликации при смене аккаунта и ответы чужого владельца: добавлены проверки поколения сессии и владельца.
- Выход из веба больше не отзывает сессию телефона: используется локальный scope выхода.
- Сдвиг времени напоминания при редактировании в другом часовом поясе: сохранение локального времени, секунд и исходного момента проверено тестом.
- Прерывание первого входа между сохранением сессии и переносом гостевых заметок: перенос безопасно возобновляется.
- Лишние синхронизации на heartbeat и накопление WorkManager-задач: события фильтруются, задания объединяются, последняя правка не теряется при завершении предыдущего запуска.

Повторное ревью не выявило новых подтверждённых P1/P2 в исправленных участках. Это не означает, что все сценарии реального устройства уже проверены.

## Развёртывание и оставшиеся проверки

**Рабочий сайт и Supabase не обновлялись.** Пользователь запросил просмотр и отдельное согласование до изменения действующей системы. SQL-проверки откатились; миграция синхронизации, FCM cron и Edge Function не развёрнуты. SSH-сервер не проверен: исходящие подключения из текущего терминала ограничены.

Firebase CLI установлен, локальный вход Google подтверждён. Доступ к API из терминала завершается DNS-ошибкой, инструменты Firebase MCP ещё не появились в текущей сессии. Firebase-проект, Android app и серверные FCM-учётные данные пока не созданы; клиентский `firebase-config.json` отсутствует. Привилегированных ключей в исходниках/APK нет.

Осталось:

1. Завершить подключение Firebase, создать проект и Android app, получить клиентскую конфигурацию и подготовить серверные учётные данные. Пересобрать APK с конфигурацией FCM.
2. После согласования владельца проверить способ запуска сервера, создать резервные копии и развернуть серверную миграцию, веб-версию и отправитель FCM.
3. Проверить браузер ↔ APK с одним аккаунтом, офлайн-конфликт в обоих порядках, удаление, повторный вход и восстановление сети через действующий Supabase.
4. Проверить настоящую FCM-доставку и фоновые переходы на телефоне, включая Doze, перезагрузку и отключённые разрешения. Android может откладывать фоновые задачи; немедленная доставка не гарантируется.
5. Сверить скриншоты с веб-версией и проверить обновление APK с сохранением локальной базы на устройстве пользователя.

До серверной миграции новый APK пригоден для локального просмотра; работающая синхронизация с production пока не заявляется.

## Установка поверх старой debug-сборки

Прежний workflow не сохранял ключ debug-подписи. Если подписи различаются, Android не установит обновление поверх старого приложения. **До удаления старого приложения нужно экспортировать заметки через Export backup и проверить файл.** Переустановка удаляет его локальную базу. Новый cache сохраняет ключ между тестовыми сборками, но может быть очищен; для постоянных выпусков нужен отдельно сохранённый release-ключ.
